请从零实现一个本地API身份认证网关，重点保证密钥轮换、签名重放防护和受保护写入在并发下保持一致。使用 Windows 原生 Python 3.12 标准库和SQLite，仅需 CPU；不使用 Docker、外部服务或现成签名认证中间件。后端业务只需提供账户记数器increment及查询接口，预置租户、服务身份和密钥，不做注册、界面或计费。

1. 明确定义并实现以下签名协议：HMAC-SHA256，签名输入为ASCII字节串 method + 换行 + 原始request-target + 换行 + 十进制timestamp + 换行 + nonce + 换行 + body_sha256。method固定大写，request-target只能是无空白的ASCII，签名覆盖原始路径和查询串，不能先解码、排序或重新编码；body_sha256为实际收到请求体的SHA256小写十六进制。key_id、timestamp、nonce、body_sha256和signature均为唯一必填头，重复头、非规范数字、超长或非法字段明确拒绝；请求体限定1MiB。服务身份和租户从key_id对应的服务端记录得出，不能相信业务请求另报的身份。
2. 每个服务身份最多同时拥有新旧两把有效密钥，支持启用新密钥、撤销指定密钥和禁用整个身份。timestamp按服务器接收时刻检查，允许前后60秒；nonce至少128位随机，唯一性范围为(租户,服务身份)，不是key_id。相同nonce即使用新旧不同密钥签名，也只能消费一次。可注入时钟必须保持非递减；nonce至少保留至该签名时间窗口完全过期，不能在原请求仍可通过时间检查时删除。无效签名或越权目标请求不能预先占用nonce。
3. 至少4个独立网关进程共享数据库。检查密钥/身份当前状态、占用nonce、increment业务写入及审计记录必须形成一次原子提交。撤销或禁用先提交后，尚未提交的旧密钥请求必须重新检查并失败；撤销返回后新开始的请求也必须拒绝。分别在nonce写入后业务未写入、业务已写入但事务未提交、事务已提交但HTTP响应未发出时真实终止自己启动的进程，重启并重放原请求，验证计数最多增加一次且不存在“nonce占了但业务没做”的已提交状态。重放已提交请求可以返回已使用，不要求重发成功响应。

交付HTTP网关、密钥管理命令、独立签名客户端、自动化并发及故障测试和Windows说明。测试覆盖原始查询串差异、请求体被改、重复认证头、新旧钥共用nonce、过期边界、签名失败后合法重试、撤销与已鉴权请求交错及跨租户同名身份。用真实HTTP请求和最终计数/审计记录核验，不能只测试签名函数。日志不得泄露密钥；写明实际结果和未完成项。
